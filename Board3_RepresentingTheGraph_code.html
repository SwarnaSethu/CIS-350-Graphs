1 — The Problem

We already did this by hand. Now: how does C# hold onto it?

a

What We Already Know

  • Five names: Ann, Ben, Cam, Dee, Eli.
  • Six friendships (edges) between them.
  • We built a 5×5 matrix of 0s and 1s by hand, checking every pair once.
b

The Question

  • On paper, "Ann" is just a name written in a box.
  • In C#, a Graph object has to hold the names, the connections, AND whether each vertex has been visited yet — all at once, all lined up correctly.
  • No new data structure is needed. Just arrays, used carefully.

2 — Three Things a Graph Needs in Code

Plus two plain variables to keep track of size. That's the whole Graph class.

1

vertices[ ] — array of strings

  • string[] — one slot per vertex.
  • vertices[i] = the name stored at position i.
  • Built once, filled in as AddVertex is called.
2

adjMatrix[ , ] — 2-D array of ints

  • int[,] — a grid, maxVertices rows by maxVertices columns.
  • adjMatrix[i, j] = 1 if vertex i and vertex j are connected, 0 if not.
  • This IS the matrix from Board 1 — just written as a 2-D array instead of drawn on paper.
3

visited[ ] — array of bools

  • bool[] — same length as vertices[ ].
  • visited[i] = true once vertex i has been printed.
  • Same index as vertices[ ] always means the same person.
4

count and maxVertices — plain ints

  • Not arrays — just two numbers.
  • maxVertices — the size the arrays were created with (set once, never changes).
  • count — how many vertices have actually been added so far.

  • In C#, the rows and columns are labeled with indices — 0 through 4 — using the exact same order vertices[ ] was filled in.
  • adjMatrix[2, 3] is row 2 (Cam), column 3 (Dee) = 1, because Cam and Dee are friends.

11 — Check Your Understanding

Answer each one yourself before reading the answer box.

Q1. What data type is vertices[ ]?
Answer: An array of strings — string[]. Fixed size, filled in one name at a time by AddVertex.
Q2. True or False: adjMatrix is a List<List<int>>.
Answer: False. It's a single 2-D array — int[,] — created once with a fixed size, not a list of lists.
Q3. What type is count? What type is maxVertices?
Answer: Both are plain int variables — not arrays. maxVertices is set once and never changes; count goes up by one every time AddVertex runs.
Q4. If a sixth friend were added, what index would they get, and which three places would the number 5 show up?
Answer: Index 5 — but only if maxVertices was at least 6, since count already equals 5 (the array is full at 5 vertices). If there were room: vertices[5], visited[5], and row/column 5 of adjMatrix.

12 — The Constructor

Five fields, set up once, the moment a Graph is created

private string[] vertices; // vertices[i] = the name at index i private int[,] adjMatrix; // adjMatrix[i, j] == 1 means an edge i<->j private bool[] visited; // visited[i] == true once i has been printed private int count; // how many vertices added so far private int maxVertices; // capacity of the arrays public Graph(int maxVertices) { this.maxVertices = maxVertices; vertices = new string[maxVertices]; adjMatrix = new int[maxVertices, maxVertices]; visited = new bool[maxVertices]; count = 0; }
CodeMeaning
vertices = new string[maxVertices]build an empty array with one slot per vertex — this is the vertices[ ] row from slides 3–7, before any name is added
adjMatrix = new int[maxVertices, maxVertices]build the grid of zeros from slide 8 — maxVertices rows by maxVertices columns
visited = new bool[maxVertices]build an array of false flags, same length as vertices[ ]
count = 0nobody has been added yet
  • All four arrays are built with the same length — maxVertices — the moment this constructor runs. That's why every index lines up across all of them, from slide 1 to the end of the program.
  • In the demo code, this runs once: Graph g = new Graph(5);.

13 — AddVertex, Line by Line

This is the exact code behind slides 3–7 — run it, and the array fills in exactly how we traced it by hand

public void AddVertex(string label) { if (count == maxVertices) throw new InvalidOperationException("Graph is full."); vertices[count] = label; count++; }
CodeMeaning
if (count == maxVertices) throw ...check there's still an open slot before trying to add anyone
vertices[count] = labelstore the new name at the next open slot — whatever count is currently pointing at
count++move count forward by one, so the next call lands in the next slot
  • Call this five times — AddVertex("Ann"), AddVertex("Ben"), AddVertex("Cam"), AddVertex("Dee"), AddVertex("Eli") — and you get exactly slides 3 through 7, one call per slide.
  • visited[ ] isn't touched here — it's already all false from the constructor.

14 — AddEdge, Line by Line

This is how the matrix in slide 8 actually gets filled in

public void AddEdge(string from, string to) { int i = IndexOf(from); int j = IndexOf(to); adjMatrix[i, j] = 1; adjMatrix[j, i] = 1; }
CodeMeaning
int i = IndexOf(from)turn the first name into its row/column number
int j = IndexOf(to)turn the second name into its row/column number
adjMatrix[i, j] = 1mark the edge in one direction
adjMatrix[j, i] = 1mark the SAME edge in the other direction
  • AddEdge("Ann", "Ben") sets BOTH [0,1] and [1,0] to 1, in one call — that's why slide 8's matrix is symmetric across the diagonal. A friendship goes both ways.
  • Six calls total — one per edge — builds the whole matrix from slide 8.

15 — IndexOf, the Shared Helper

AddEdge calls this twice. DFS and BFS will call it too, later.

private int IndexOf(string label) { for (int i = 0; i < count; i++) { if (vertices[i] == label) return i; } throw new ArgumentException("No such vertex: " + label); }
CodeMeaning
for (int i = 0; i < count; i++)walk through vertices[ ] left to right, one slot at a time
if (vertices[i] == label) return ifound it — this is the index that belongs to that name
  • A plain left-to-right search through vertices[ ] — nothing clever, just checks each name in order.
  • This is the one place a name ever turns into an index. Every other method — AddEdge now, DFS and BFS later — works with the index it gets back, never the name directly.

16 — DFS: Why Do We Need GetUnvisitedNeighbor?

Starting from a vertex, DFS needs to answer one question: is there anywhere new to go from here?

private int GetUnvisitedNeighbor(int v) { for (int j = 0; j < count; j++) { if (adjMatrix[v, j] == 1 && !visited[j]) return j; } return -1; // dead end -- every neighbor already visited }
CodeMeaning
for (int j = 0; j < count; j++)scan vertex v's whole row of adjMatrix, left to right
if (adjMatrix[v, j]==1 && !visited[j])is j actually connected to v, AND not visited yet?
return jfound one — hand back its index
return -1checked every column, nobody new — this is a dead end
  • Scanning in index order (0, 1, 2, 3, 4) every time is exactly why DFS picks Ben before Cam when starting from Ann — Ben's index (1) is smaller than Cam's (2).
  • This is the same row we highlighted back in slide 8 and slide 9 — GetUnvisitedNeighbor is just reading across one row of the matrix.

17 — The Full DFS Method

Push the start. Peek the top. If it has somewhere new to go, push there. If not, pop and back up.

public void DFS(string startLabel) { for (int i = 0; i < count; i++) visited[i] = false; int start = IndexOf(startLabel); IntStack stack = new IntStack(); visited[start] = true; Console.Write(vertices[start] + " "); stack.Push(start); while (!stack.IsEmpty()) { int current = stack.Peek(); int next = GetUnvisitedNeighbor(current); if (next == -1) { stack.Pop(); } else { visited[next] = true; Console.Write(vertices[next] + " "); stack.Push(next); } } Console.WriteLine(); }
CodeMeaning
visited[i] = false (for every i)start with nobody visited
int start = IndexOf(startLabel)turn the starting name into an index
stack.Push(start)put the starting vertex on the stack
while (!stack.IsEmpty())keep going until the stack is empty
int current = stack.Peek()look at the top of the stack WITHOUT removing it
int next = GetUnvisitedNeighbor(current)ask: does current have anywhere new to go?
if (next == -1) stack.Pop()dead end — back up
else { visited[next]=true; print; stack.Push(next); }found somewhere new — go there
  • Peek, not Pop, at the top of the loop. We only remove (Pop) a vertex once we've confirmed it has no unvisited neighbor left. If we popped first, we'd lose our place and couldn't tell where to keep exploring from.
  • This is IntStack doing exactly what slide 9 of Board 2 showed by hand — push to go deeper, pop to back up.

19 — The Full BFS Method

Dequeue one vertex. Enqueue ALL of its unvisited neighbors before moving on to the next one.

public void BFS(string startLabel) { for (int i = 0; i < count; i++) visited[i] = false; int start = IndexOf(startLabel); IntQueue queue = new IntQueue(); visited[start] = true; Console.Write(vertices[start] + " "); queue.Enqueue(start); while (!queue.IsEmpty()) { int current = queue.Dequeue(); for (int j = 0; j < count; j++) { if (adjMatrix[current, j] == 1 && !visited[j]) { visited[j] = true; Console.Write(vertices[j] + " "); queue.Enqueue(j); } } } Console.WriteLine(); }
CodeMeaning
queue.Enqueue(start)put the starting vertex in the queue
while (!queue.IsEmpty())keep going until the queue is empty
int current = queue.Dequeue()take the FRONT vertex out of the queue
for (int j = 0; j < count; j++)check every possible neighbor of current, in order
if (adjMatrix[current, j]==1 && !visited[j])is j actually connected, AND not visited yet?
visited[j]=true; print; queue.Enqueue(j)yes — visit j now, and queue it so its neighbors get checked later
  • visited[j] is set to true the moment j is ENQUEUED, not when it's later dequeued. That's what stops the same vertex from being added to the queue twice when two different vertices both connect to it.
  • This is the one real difference from DFS: DFS pushes a single neighbor and loops back to Peek again; BFS's inner for-loop enqueues every unvisited neighbor of current before moving on.

21 — Key Takeaways

The whole Graph class, start to finish

What We Covered

  1. A Graph object is just three arrays — vertices[ ], adjMatrix[ , ], visited[ ] — plus two plain ints, count and maxVertices.
  2. vertices[ ] is a string array; adjMatrix is a 2-D int array; visited is a bool array. No Lists, no Dictionaries.
  3. AddVertex fills the next open slot and moves count forward by one.
  4. adjMatrix is the exact same matrix from Board 1 — just indexed by number instead of drawn by hand.
  5. One index always means the same vertex across all three structures.
  6. The constructor builds all four fields at once; AddVertex fills vertices[ ]; AddEdge fills adjMatrix[ , ]; IndexOf is the one place a name ever turns into an index.
  7. DFS pushes to go deeper and pops to back up, using Peek first to check before ever removing — GetUnvisitedNeighbor is the question "is there anywhere new to go?", answered by reading one row of adjMatrix.
  8. BFS dequeues one vertex and enqueues ALL of its unvisited neighbors at once, marking them visited right at enqueue time.
  9. Both traces match Board 2 and Program.cs exactly: DFS = Ann Ben Dee Cam Eli, BFS = Ann Ben Cam Dee Eli.

The Whole Story

  • Every method in Graph.cs — constructor, AddVertex, AddEdge, IndexOf, GetUnvisitedNeighbor, DFS, BFS — is just reading or writing vertices[ ], adjMatrix[ , ], or visited[ ] by index.
  • DFS vs. BFS is really just IntStack vs. IntQueue — same graph, same starting point, two different visiting orders.
  • Run Program.cs and the printed output should match these traces exactly. The full explanatory handout (Part 2) covers this same code, line by line, for independent review.
