One example carries through the whole board: five friends on a social app — Ann, Ben, Cam, Dee, Eli.

1 — What is a Graph?

Vertices + edges — no required order, no required root

The example graph — who's friends with whom (undirected, unweighted)
a

The Definition

  • A graph is just vertices + edges.
  • Unlike a tree, there's no required root and no required parent/child order — any vertex can connect to any other.
  • Real-world example: on a social app, each person is a vertex. "Ann and Ben are friends" is an edge. The whole friend network is a graph.
b

What a Graph Answers

  • Questions a list or tree can't easily answer: "is everything connected?" and "what's the shortest way from X to Y?"
  • Other real graphs, same idea: cities connected by roads/flights, web pages connected by links, computers connected by cables, tasks connected by "must finish before."
  • Part 3 covers the full list of applications.

2 — Vocabulary

The handful of terms everything else is built on

b

Terms

  • Vertex (or node) — one "thing" in the graph. Plural: vertices.
  • Edge — a connection between two vertices.
  • Adjacent — two vertices connected by an edge are adjacent (neighbors).
  • Degree — how many neighbors a vertex has. (Cam has degree 3: Ann, Dee, Eli.)
  • Undirected graph — edges go both ways (friendship).
  • Directed graph — edges are one-way (following someone on social media without them following back).
  • This class: undirected, unweighted graphs only.

3 — Applications of Graphs

The same vertices-and-edges idea, showing up everywhere

Social Networks
People are vertices, friendships/follows are edges. Finding "friends of friends," or how closely two people are connected, is a graph traversal.
vertex = person · edge = friend/follow
Maps & Navigation
GPS apps like Google/Apple Maps model intersections as vertices and road segments as edges, then search the graph for the shortest route.
vertex = intersection · edge = road
The Web
Every web page is a vertex; every hyperlink is a directed edge. Search engines crawl this graph to discover and rank pages.
vertex = page · edge = hyperlink
Flight Networks
Airports are vertices, direct flight routes are edges. Airlines use this to plan layovers and you use it to find the cheapest/fastest trip.
vertex = airport · edge = direct flight
Course Prerequisites / Scheduling
Tasks or courses are vertices; "must finish before" relationships are directed edges. Figuring out a valid order to take them is a graph problem (topological sort).
vertex = course/task · edge = prerequisite
Computer Networks
Routers/computers are vertices, physical or logical connections are edges. Routing a packet across the internet is finding a path through this graph.
vertex = device · edge = connection

Notice the pattern: every example is just "things" + "connections between things." If a real-world problem is about connections, it's probably a graph problem.

4 — Representing a Graph in Code: Two Ways

Before we build either one, here's what we're building toward

  • We know what a graph is now — vertices and edges. To actually use one in a program, we need to store it somehow.
  • There are two standard ways to do this: the adjacency matrix (a grid of 0s and 1s) and the adjacency list (each vertex keeps its own short list of neighbors).
  • Same graph, same information either way — just organized differently, with different trade-offs.
a

Adjacency Matrix

  • A grid: one row and one column per vertex. 1 means connected, 0 means not.
  • We'll build this one first, by hand, checking every pair.
b

Adjacency List

  • Each vertex keeps a short list of just its actual neighbors — nothing written down for pairs that aren't connected.
  • We'll look at this one right after the matrix is built.

17 — Adjacency List

Storing the graph as each vertex's own contact list

Ann → Ben, Cam
Ben → Ann, Dee
Cam → Ann, Dee, Eli
Dee → Ben, Cam, Eli
Eli → Cam, Dee
  • Each vertex keeps only its own neighbors — nothing is stored for pairs that aren't connected.
  • Real-world read: like each person's own contact list — only the friends they actually have.
  • To check "are Ann and Cam friends?" you scan Ann's (short) list instead of jumping to one cell.
  • Much smaller for a sparse graph (next few slides define exactly what that means).

18 — Which One, and When?

Same graph, two valid formats, different trade-offs

 Space"Are X, Y connected?""List all of X's neighbors"Best for
Adjacency MatrixO(V²) — always, no matter how few edgesO(1) — one lookupO(V) — scan the whole rowSmall or dense graphs; simple code
Adjacency ListO(V + E) — only pays for edges that existO(degree) — scan that vertex's listO(degree) — the list is the answerLarge, sparse, real-world graphs

V = number of vertices, E = number of edges, degree = how many neighbors a vertex has.

19 — Dense vs. Sparse, Defined

Not just adjectives — something you can compute

  • For V vertices, the most edges an undirected graph could possibly have is V(V-1)/2 — every vertex connected to every other.
  • Dense graph: actual edges are close to that maximum. Sparse graph: actual edges are far below it.
Dense — 6 vertices, 12 of 15 possible edges
Sparse — 6 vertices, 5 of 15 possible edges
ExampleVMax possible edgesActual edgesDense or sparse?

Small, tight-knit graphs tend to look dense. Real-world graphs almost always get sparser as they grow — you gain vertices much faster than you gain edges per vertex.

20 — Real-World Judgment Calls

Which would you actually pick?

Round-robin tournament bracket
→ Matrix
8–16 players, everyone plays everyone — nearly V(V-1)/2 edges (dense), V is small either way, and you'll constantly ask "did A already play B?" — O(1) lookup wins outright.
A small town's road map
→ List
~50 intersections, but each one only connects to 3–4 nearby streets — most pairs are NOT directly connected. Sparse, so a matrix wastes space on mostly-0 cells.
Instagram's follower graph
→ List (mandatory)
Billions of users, a few hundred follows each. A matrix would need (billions)² cells — physically impossible to store. The list is the only option.
Our 5-friend example
→ Matrix (for THIS reason only)
Not because real friend networks are dense — they aren't. The matrix works well here because V is tiny (5), so O(V²) costs nothing, and the resulting code stays simple and easy to trace by hand.

The real rule of thumb: ask "how big will V get, and how sparse will it stay?" A small or naturally dense graph (tournament brackets, a handful of related tasks) → matrix. Anything that scales up with a roughly fixed number of connections per vertex (social networks, road maps, the web) → list, every time.

21 — Key Takeaways

Before we move to Board 2 (DFS & BFS)

What We Covered

  1. A graph is vertices + edges — no required order or root.
  2. Vocabulary: vertex, edge, adjacent, degree, directed vs. undirected.
  3. Graphs model social networks, maps, the web, flights, prerequisites, and computer networks.
  4. Two ways to store a graph: adjacency matrix (grid) and adjacency list (per-vertex neighbor lists).
  5. The choice depends on density and scale, not "correctness."

Carrying Forward

  • The code we'll build uses the matrix — it matches the textbook and keeps the implementation simple for a graph this small, not because it's the "better" choice in general.
